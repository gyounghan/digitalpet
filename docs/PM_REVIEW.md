## 1. 전체 평가 (TL;DR)

**성공 가능성 있음. 단, 성공의 열쇠는 배틀이 아니라 "애착 + 저마찰 리텐션"이다.**

- 이 장르는 검증된 시장이다. Finch(자기관리+펫 애착), Pikmin Bloom(걷기+수집), Walkr가 이미 증명했다. PocketFriend와 가장 가까운 성공 사례는 Finch.
- Finch의 성공 공식 핵심은 **"펫이 절대 유저를 벌하지 않는다"**. PocketFriend는 현재 그 반대 방향 장치(사망, 감쇠 가속, 랭킹, 패배 페널티)를 여럿 갖고 있다. 이것을 어떻게 다루느냐가 성패를 가른다.
- 구현 완성도는 이미 높다(감쇠 그리드, delta 기반 건강 연동, 배틀 시뮬레이션, 위젯까지 동작). 지금 필요한 것은 **기능 추가가 아니라 톤 조정과 범위 축소**다.

## 2. 핵심 강점

### ① 도트 파이프라인 = 사업적 자산
이미지 에셋 없이 좌표 데이터(`lib/core/pixel/`)로 렌더링하는 구조라 신규 종·모션·**코스메틱**의 한계비용이 극도로 낮다. 나중에 꾸미기 수익화와 직결된다. (팔레트 스왑만으로 색상 변형 상품이 나온다.)

### ② Lv5 종 분기 = 최고의 공유 포인트
"내 생활 패턴이 나를 백호로 만들었다"는 사실상 성격 테스트(MBTI) 감성. 마케팅 예산 없이 퍼질 수 있는 거의 유일한 훅이다.
- 현재는 도감 구석에 있는데, **종 결정 순간을 의식(ceremony)급 연출**로 키우고 **결과 카드 공유** 기능을 붙여야 한다.
- "활발×자유 = 주작" 같은 판정 근거("이번 주 4만 보를 걸었고, 식사 시간이 자유로웠어요")를 카드에 함께 보여주면 공유 욕구가 커진다.

### ③ 오프라인 우선 설계
서버가 죽어도 앱이 완전 동작(온라인 배틀·랭킹 제외). 1인 운영에 결정적으로 유리하다. 서버 비용·장애 리스크가 앱 생존과 분리돼 있다.

### ④ 배틀 스탯이 이미 "건강 성적표"로 설계됨
HP=누적 걸음, ATK=행복(=운동), DEF=기력(=폰 미사용/수면), 컨디션 보정=오늘의 돌봄 상태. **배틀이 정체성과 충돌하지 않는 구조가 이미 코드에 있다.** 부족한 것은 결과 화면의 "해설"뿐이다.

## 3. 핵심 위험 (우선순위 순)

### ① 사망 시스템은 "복귀 유저 킬러"다 — 최우선 수정
- 세 스탯 모두 0으로 5일 = 현실적으로 **앱을 1~2주 안 연 사람**에게만 발생한다.
- 즉 이 기능이 발동하는 유일한 대상은 **돌아온 이탈 유저**이고, 그 사람을 시체 + 광고 시청 요구로 맞이하는 구조다. 복귀 전환율을 정면으로 깎는다.
- **대안: 사망 → "긴 잠(겨울잠)" 또는 "여행을 떠남"으로 리프레이밍.**
  - 돌아오면 펫이 "보고 싶었어!"로 맞이하고, 스탯 낮은 상태로 재시작.
  - 광고는 "즉시 완전 회복" 옵션으로 남기면 수익 포인트도 유지된다.
  - 3회차 레벨 -1 패널티는 삭제 권장(처벌 요소 제거).
  - 구현 비용: `shouldDie`/`resurrect` 경로의 연출·문구 교체 수준으로 낮다. 위젯의 dead 표기도 잠자는 도트로 교체.

### ② "폰 미사용 = 기력" 루프의 내재 모순
- 앱은 유저가 자주 열길 원하는데, 핵심 루프는 "폰을 내려놔라"다.
- 이 긴장을 푸는 것이 **홈 위젯**이다 — 앱을 안 열어도 펫이 보이는 유일한 표면. 위젯은 부가 기능이 아니라 **핵심 UX로 승격**해야 한다.
- iOS 위젯 부재는 로드맵상 큰 구멍임을 인지할 것.

### ③ 복잡도 — 규칙이 아니라 "노출"을 지워라
- 세트 반감(60→30→15…), 티어업 보너스, 카테고리 3회 캡, 배틀 배수(1.0/0.7/0.5), 상성, 등급 2단계… 설계자도 표를 봐야 아는 수준.
- 규칙 자체는 밸런스 장치로 유효하니 **유저에게 보이는 것만 줄인다**: "오늘의 목표 3줄 + 세트 보상"까지만 노출. 반감·캡·배수는 내부 로직으로 숨김. (UI 정보 다이어트로 절반은 이미 해놓음.)

### ④ 랭킹 = 건강 앱에서 검증된 이탈 요인
- 비교 압박은 습관 앱의 안티패턴. 게다가 초기엔 유저풀이 없어 **랭킹판이 텅 비어 "죽은 앱" 인상**을 준다.
- MVP에서 탭 자체를 숨길 것(코드는 유지, feature flag 처리).

### ⑤ 플랫폼/운영 리스크 (조용하지만 치명적)
- Health Connect 권한 온보딩 마찰(설치 유도, 권한 화면 이탈).
- 제조사 배터리 최적화로 WorkManager 15분 주기가 안 지켜지는 기기 다수 → catch-up 로직이 있어 완화되지만, 온보딩에서 배터리 최적화 예외 안내 필요.
- 서버 URL이 `10.0.2.2:3000`(에뮬레이터 전용) 하드코딩 — 출시 전 필수 교체.

## 4. 포지셔닝 제안

> **"내 생활 습관으로 강해지고 진화하는 작은 친구"** — 유저가 제시한 이 문장이 정확하다.

- 건강 앱 문법(그래프, 목표 달성률, 스트릭 압박)을 버리고, **펫이 유일한 인터페이스**가 되게 한다. 유저는 숫자를 관리하는 게 아니라 친구를 돌본다.
- 배틀은 "전투 콘텐츠"가 아니라 **"내가 잘 돌봤는지 확인하는 거울"**로 포지셔닝한다.

## 6. 배틀 시스템 — 유지 방향

### 개발 순서 (5개 대안 평가)

1. **AI 배틀 — MVP. 이미 완성됨.** 서버 불필요, 하루 3회, 건강으로 강해진 펫 확인. 여기에 "결과 해설"만 붙인다.
2. **친구 스냅샷 PvP — 2차. 강력 추천.**
   - 코드/QR로 친구 펫 스냅샷을 불러와 로컬 시뮬레이션. 서버·운영 부담 0.
   - "내 펫 코드 줄게, 이겨봐" — 오프라인 바이럴을 만든다.
   - `PetModel.toJson`이 이미 있어 직렬화 구현 난도 낮음. 스냅샷을 압축+base64 코드 또는 QR로.
3. **비동기 PvP — 3차.** 유저가 모인 뒤. 서버에 스냅샷 등록 → 상대가 내 펫과 싸움 → 결과 알림. 기존 NestJS 재활용. 실시간 매칭 문제(빈 큐)가 없어 초기 유저 규모에 강하다.
4. **로컬 PvP** — 친구 스냅샷 PvP에 흡수됨(같은 기기 입력도 코드 입력의 특수 케이스). 별도 개발 불필요.
5. **실시간 PvP — 보류.** 이미 만들어놨지만 초기엔 끈다. 비동기 PvP가 자리 잡은 후 주말 이벤트성으로 켜는 자산.

### 네이밍과 톤

- **추천: "대련"** — 승패가 아니라 실력 확인이라는 뉘앙스. 살벌하지 않고 성장 서사와 맞는다.
- "사신수 시련"은 나중에 PvE 스테이지 콘텐츠(보스 시련) 이름으로 아껴둔다.
- 친구전은 "친구 대련"으로 통일.

### 전투 규칙 (현행 유지 + 소폭 수정)

현행 구조는 이미 요구사항에 부합한다:
- 자동 시뮬레이션 7턴, 유저 선택은 스타일(공/균/방) 3택 — 적절. 유지.
- 상성 유리 ×1.2만 있고 불리 페널티 없음 — **좋은 설계**(처벌 없는 보너스만). 유지.
- 종별 스킬 4종 — 개성 부여. 유지.
- 추가 제안: "오늘의 응원 아이템 1개"는 **일일 이벤트와 통합**(모험의 날 = 자동 응원)하거나 2차로 미룬다. MVP에서 선택지를 늘리지 말 것.

### 전투 스탯 공식 (현행 = 이미 정답)

```
ATK = (5 + 레벨 + 세트보너스 + 진화단계보너스 + 종보너스) × 행복 보정(±20%)
DEF = 같은 base × 기력 보정(±20%)
HP  = (50 + 레벨×2 + 누적걸음보너스 + 종보너스) × 포만감 보정(±20%)
```
- "많이 걸으면 HP, 행복하면 ATK, 기력 좋으면 DEF, 잘 먹으면 지속력" — 요구한 매핑이 이미 코드에 있다. 공식 변경 불필요.
- **필요한 것은 이 인과를 유저에게 보여주는 결과 화면뿐이다.**

### 배틀 결과 화면 = "성장 확인" 리포트 (핵심 신규 작업)

승패 배너를 줄이고, 스탯 기여 해설을 메인으로:
- "오늘 8,200보를 걸어서 HP가 끝까지 버텨줬어" (걸음→HP 기여가 판정에 유효했을 때)
- "기력이 82라 방어를 잘했어" (DEF 보정이 +일 때)
- "포만감이 40이라 중반에 지쳤어. 내일 아침 밥 주면 더 강해질 거야" (패배 시 — 원인+처방)
- 패배 문구에서 금지: "약하다", "졌습니다" 단독 표기. 항상 "내일 이렇게 하면"의 처방과 세트로.
- 구현: 전투 스탯이 전부 건강 지표에서 파생되므로 **데이터는 이미 있다.** 시뮬레이션 결과(보정 부호, HP 잔량, 턴 수)에서 해설 문구를 고르는 순수 함수 하나면 된다. → 유닛 테스트 대상으로 최적.

### 보상 구조

- 승 50 / 압승 70 / 패 15 EXP 유지. **패배에도 15를 주는 현행 설계는 좋다** (참가 자체가 이득).
- 하루 3회 배수(1.0/0.7/0.5)는 유지하되 UI에 숫자로 노출하지 말 것 ("오늘의 대련 1/3"만 표시).

## 7. 펫 애착 UX

1. **이름 + 첫 만남 연출**: 알/털뭉치 상태에서 이름 짓기, 첫 반응 애니메이션. (이름은 이미 있음 — 연출 보강.)
2. **대사가 데이터를 언급**: "오늘 많이 걸었네! 나도 신나!" — 기분 대사에 실제 걸음 수·수면을 섞으면 "나를 지켜보는 친구" 감각이 생긴다. 현재 mood별 fallback 대사 시스템에 활동 데이터 조건 분기만 추가.
3. **터치 상호작용**: 펫 탭 → 반응 모션 + 한마디. 비용 낮고 애착 효과 큼.
4. **주간 회고 카드**: "이번 주 우리: 4.2만 보, 세트 5개, 대련 3승" — 공유 가능 이미지. 사신수 카드와 함께 바이럴 표면.

## 8. 사신수 진화 개선

1. **진화 예고**: Lv4에서 "곧 내 모습이 정해질 것 같아…" 티저. 현재 축 기울기를 은유로 힌트("요즘 우리 많이 돌아다녔지?").
2. **결정 순간 연출**: 풀스크린 도트 연출 + "당신의 생활이 주작을 깨웠습니다" + 판정 근거 2줄.
3. **결과 카드 공유**: 종 + 근거 + 도트 이미지. (공유 기능은 2차여도 좋으나 연출은 MVP.)
4. **superior/mythical 조건 가시화**: 도감 진화 트리에 "은은한 실루엣 + 진행 게이지"로. 숫자 조건(운동 40회 등)은 게이지로만, 텍스트 명시는 하지 않음(압박 방지).
5. 종별 성장 배율(주작 행복 ×1.3 등)은 도감에 "성격"으로 서술: "주작은 신나는 걸 좋아해요" — 숫자 대신 캐릭터성으로.

## 9. 홈 위젯 — 리텐션 핵심으로

- 위젯이 "폰을 덜 봐라"와 "펫을 잊지 마라"의 모순을 푸는 유일한 표면이다.
- 개선 순서:
  1. 위젯에 **오늘 걸음 진행 미니 게이지** 추가 (걸음/목표 1줄) — 위젯만 봐도 오늘 할 일이 보이게.
  2. 기분 변화 시 위젯 즉시 갱신은 이미 구현됨 — 유지.
  3. dead 표기를 "잠자는 도트"로 교체 (사망 리프레이밍과 세트).
  4. (2차) 위젯 탭 시 밥주기 딥링크 — 앱 진입 마찰 제거.
- iOS 위젯(WidgetKit)은 iOS 출시 시점의 필수 항목으로 로드맵에 명시.

## 10. 알림/대사 톤 가이드

- **금지**: 죄책감 유발("펫이 굶고 있어요!", "3일째 안 왔어요"), 명령형, 느낌표 남발.
- **권장**: 펫 1인칭 + 가벼운 제안. "산책 갈까? 나 몸이 근질근질해", "배가 살짝 고파졌어".
- 하루 최대 3회 제한(현행)은 유지. 밤 시간대 알림 금지 확인.
- 복귀 유저 첫 알림/첫 화면은 무조건 환영: "돌아왔구나! 보고 싶었어."

## 11. 수익화

- **광고 부활 단독은 부적합** — "죄책감 수익화"라 정체성과 정면 충돌. (사망 리프레이밍 후에는 "즉시 완전 회복" 광고로 완화 유지.)
- **주력은 꾸미기/테마**: 도트 팔레트 스왑(색 변형), 배경 무대, 모자/소품, 위젯 테마.
  - 도트 파이프라인 덕에 코스메틱 원가가 거의 0 — 이 앱의 구조적 이점과 정확히 맞물린다.
  - 판매 화폐는 현금 직접 결제보다 "일일 목표로 버는 재화 + 소액 IAP 병행"이 톤에 맞는다.
- 구독(테마 전체 + 광고 제거)은 유저 1만 이후 검토.

## 12. 첫날 / 7일차 경험

**Day 1 (목표: 첫 세션 5분, 당일 재방문 1회)**
1. 온보딩 3장 이내 → 이름 짓기 → 권한 요청(걸음만 필수, 나머지 나중에)
2. 첫 밥주기 튜토리얼 → 펫 반응
3. 첫 목표는 레벨 무관 초저가(걸음 1,000보)로 당일 달성 보장 → 첫 EXP + 축하
4. 위젯 설치 유도 (설치 시 소액 보상)
5. 저녁 알림 1회: "오늘 같이 걸어서 즐거웠어"

**Day 7 (목표: 종 결정 도달)**
- EXP 곡선상 일일 목표를 절반만 해도 Lv5(종 결정)가 5~7일 차에 오도록 초반 곡선 확인 (현행 Lv1~3 필요 EXP 50은 적절, Lv4~5 구간 실측 필요).
- **7일 차 이벤트 = 종 결정 연출**이 첫 주 리텐션의 정점이 되도록 설계. 연속 접속 보상(+10/+25/+50/+100)이 7일 차에 걸리게 배치.

## 부록: GPT 프롬프트에 대한 피드백

작성한 프롬프트는 좋은 편이다. 특히:
- "배틀 유지" 제약을 앞에 박아 "배틀 빼세요"류 회피 답변을 차단한 것
- 배틀 대안 5개 + 순서 요구, 좋은/나쁜 방향 예시("오늘 많이 걸어서 버텼다" vs "졌으니 약하다")

보완 2가지:
1. **산출물 23개는 과하다.** 한 번에 요구하면 항목당 3~5줄짜리 얕은 답이 나온다. 3회 분할 권장: ①1~9(평가/MVP) ②10~17(배틀/진화/위젯) ③18~23(수익화/로드맵). 각 회차 끝에 "가장 자신 없는 판단 1개를 스스로 지적하라"를 추가하면 품질이 올라간다.
2. **판단 기준이 없다.** "1인 개발, 마케팅 예산 0, 한국 시장 우선, 목표 D30 리텐션 15% / MAU 1만" 같은 현실 조건을 한 문단 추가하면 평가가 훨씬 날카로워진다. 비교 대상(Finch, Pikmin Bloom, Walkr) 명시도 권장.
